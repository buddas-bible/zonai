# Reuse transformed stationary analytic shapes across swept time samples

Each moving-solid swept flux integration builds a complete `BuildDisjointAnalyticShapes(intermediate)` list for each interpolated timestamp. This is necessary because moving geometry and shape-pair overlap can change at any intermediate pose, but each stationary shape's transformed analytic circle/polygon/capsule/rounded-polygon geometry and world AABB remain **exactly the same** across samples.

The new **default-ON** `setAnalyticCutCellSweptStaticShapeReuseEnabled(bool)` uses a local `sweptStaticShapeCache2` inside `updateSweptSolidFlux`. It activates only when disjoint analytic geometry is selected, at least three obstacles are present, and at least two initial temporal samples are planned. The shape is stationary when its start and finish transforms have zero translation and shortest-path rotation difference. Dynamic and kinematic shapes with a changed transform are always rebuilt.

On first access, a stationary shape's analytic representation and world AABB are built with the original `TryGetAnalyticCircle/Capsule/Polygon/RoundedPolygon` order and `ComputeShapeAABB`, and stored. On later intermediate timestamps, the same representation is copied into the current sample's candidate list. **Input geometry validation and every pairwise `AreDisjointFluidShapes` test remain fresh, in original owner order, every sample.** Thus moving/static intersections still force the original sampled-union fallback when necessary; the cache does not store separation outcomes. The two-shape overlap and containment special cases are never cached.

The cache exists only for this one swept time interval and its optional adaptive refinement passes. A later World/Fluid Step or a `clear()` starts with a fresh cache. Separate current-Step geometry, pressure constraint assembly and pressure-after-boundary synchronization still use their original code paths. The cache is O(number of obstacle representations), rather than the quadratic pair table rejected in PR #308. The reference code remains selectable with `setAnalyticCutCellSweptStaticShapeReuseEnabled(false)`.

`fluidSweptFaceFlux2::builtStaticAnalyticShapes` and `reusedStaticAnalyticShapes` report how many stationary analytic shapes were first built or reused during the **current** swept interval. They reset with the existing swept diagnostics, and remain zero when reuse is disabled.

**Regression:** Paired ON/OFF differential simulation of actual moving dynamic and kinematic circles plus 16/48 static circles at 0.5m/0.25m grids over multiple frames, including adaptive swept refinement. A second scene includes moving/rotating polygon and capsule bodies and an immovable analytic circle. The suite compares exact swept flux and mismatch, pressure convergence and continuity, each obstacle's force/torque and the fluid momentum. The cache's hit counts and `clear()` option preservation are checked.

**Benchmark:** `fluidPreconditionerBenchmark --swept-static-shapes-sweep` compares matched cache ON/OFF runs for 0/16/48 static obstacles at both grid resolutions, measuring the **moving second Step**, swept-stage and full-Step medians, flux/mismatch diagnostics, PCG convergence, and analytic cache build/reuse counts on the same Windows Release CI runner. All performance values are informational; merge only if actual benefit justifies the added state and code.
