# Moving-only disjoint analytic swept flux

`fluidField2::updateSweptSolidFlux` integrates solid-normal volume flux at interpolated obstacle poses, and must **not** reuse current-step analytic geometry for these intermediate positions. Previously, even if only one of 50 disjoint shapes moved, every MAC face was clipped against every shape for every swept time sample.

For **three or more analytically disjoint shapes** in a given time sample, the selected geometry is the sum of individual exposed intervals. With `setAnalyticCutCellMovingSweptFacesEnabled(true)` (default), the swept integrator clips those faces only against shape indices whose **transforms have changed** since the previous snapshot: nonzero translation/time-step velocity or nonzero shortest-path angular speed. It retains input owner order, U-then-V face order, the same per-owner flux formula and the same interpolated geometry **for every time sample**. Motion is detected from transforms, **not inverse mass**: a kinematic obstacle with inverse mass zero but a changed transform still contributes swept flux. Immovable bodies contribute zero by the existing time-path definition even when their instantaneous velocity fields happen to be nonzero.

The original `ForEachAnalyticFacePortion` remains the reference when the toggle is OFF, when only two shapes exist, or whenever the disjoint analytic path falls back to sampled geometry. The two-circle overlap/containment ownership logic is unchanged. The optimization does not skip geometry validation and cannot reuse stale collision disjointness classifications from a different intermediate pose.

The differential regression covers 16/48 stationary circles, a translating movable circle, and a translating kinematic circle, using 0.5m/0.25m cell sizes and three consecutive snapshots. It compares swept diagnostics, pressure convergence, predicted continuity, per-body feedback, and fluid momentum. One configuration exercises adaptive swept sampling. `clear()` preserves the selected toggle.

The new `fluidPreconditionerBenchmark --swept-motion-sweep` explicitly advances an obstacle snapshot and measures the **second**, genuinely moving Field step. It reports medians for swept processing, full Field Step, swept sample count, total absolute flux, geometry mismatch and coupled convergence for 0/16/48 static obstacles on the same Windows Release runner. This avoids misleading cold-step microbenchmarks with zero swept work. Timings are informational; no FPS or expected-speedup threshold is a CI gate.
