# Reuse static-static separation decisions across swept time samples

The moving-solid swept flux integrator evaluates `BuildDisjointAnalyticShapes(intermediate)` at every interpolated timestamp. The builder validates shape pairs in input order, taking the fast AABB-outside path or a GJK distance check when their bounds overlap. With many immovable obstacles and multiple temporal samples this repeatedly checks the same static-static pairs even though their transforms cannot change during that swept interval.

The optional, **default-on** `setAnalyticCutCellSweptStaticPairCacheEnabled(bool)` creates a local, per-`updateSweptSolidFlux` byte-valued pair cache **only for scenes with 3+ shapes, 2+ stationary owners and 2+ time samples**. An owner is stationary when its actual transform displacement and shortest-path angular change are both zero, regardless of inverse mass or any instantaneous velocity field. For highly fragmented fields, the cache is capped at 512 total Shape owners (at most 512² pair bytes); larger scenes retain the uncached reference path rather than allocate unbounded quadratic scratch. A pair of stationary owners is classified once (disjoint or not disjoint), using the same `AreDisjointFluidShapes` path as before. Subsequent samples reuse that specific separation result. The cache preserves the same input-order early-fallback logic for overlapping geometry.

**Crucially, every pair involving at least one moving owner is evaluated from scratch at every interpolated timestamp**, with its current transform and AABB. `BuildDisjointAnalyticShapes` still reconstructs the whole intermediate-time analytic geometry and performs moving/static and moving/moving validation. In particular, a moving obstacle can become intersecting during the path and correctly switch the swept calculation from analytic disjoint clipping to the existing sampled fallback. No current-step analytic cache is reused for intermediate geometry.

The cache's `unknown/disjoint/not-disjoint` bytes are local to one swept integration and continue across optional adaptive temporal refinements of that *same* interval. New Fluid steps, reset history, `clear()`, or changes in obstacles automatically start with an empty pair cache. No state is copied between different World snapshots. When the toggle is OFF, `BuildDisjointAnalyticShapes` follows the original pairwise reference path. With fewer than two static owners or only one temporal sample, the cache has no quadratic allocation.

Two informational diagnostics on `fluidSweptFaceFlux2` report `cachedStaticSeparationPairs` (repeat comparisons avoided) and `evaluatedStaticSeparationPairs` (unique comparisons evaluated and stored during that interval). They are both zero in the reference path and reset with swept diagnostics every step.

**Validation:** The existing moving-only analytic swept regression now runs with static-pair cache OFF and ON for 16/48 immovable circles, two moving circles including a kinematic body, 0.5m/0.25m grids and an adaptive temporal-sampling case. It compares swept flux, pressure convergence, predicted continuity, per-body forces, fluid momentum and clear/toggle persistence. A separate moving-circle crossing scenario forces a *moving/static overlap* at intermediate timestamps to verify the cached static-static pairs do not conceal sampled fallback.

**Measurement:** `fluidPreconditionerBenchmark --swept-static-pairs-sweep` compares actual moving second Steps in matched reference/cache modes on the same Windows Release CI runner (0/16/48 statics; 0.5m/0.25m cells). The CSV reports swept time, full-Step time, flux, geometry mismatch, PCG convergence and both pair counters. CI measurements are informational: merge decisions should consider whether caching truly improves relevant static-heavy scenes, not merely whether it preserves correctness.
